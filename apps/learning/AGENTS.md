# apps/learning — project notes (Quranic Teacher LMS)

Read the repo-root `CLAUDE.md` first for monorepo-wide rules; this covers only this app.

- **Static export UI + Worker API.** `next.config.ts` sets `output: "export"` and `basePath` from `NEXT_BASE_PATH` (`/learning` in production, unset in `npm run dev`). There is no Next.js server code (no middleware, no `src/app/api`). All data goes through the browser client `src/lib/db.ts` (`db.from().select()…`, `db.rpc()`, `db.auth`, `db.channel()`) to the Worker API under `/learning/api` (`worker/api`). **The Worker is the only enforcement** — `worker/api/policies.js` (per-table row rules), `schema.js` (table/column whitelist), `query.js` (compiler), `hooks.js` (bookkeeping, audit log, progress seeding); UI role gating is UX only. Do not add Node-server features (route handlers, server actions, SSR cookies, `rewrites()`/`redirects()`, `next/image` optimisation). Full backend docs: `BACKEND.md`.
- **Hosting: Cloudflare Workers** (Worker `iqraspace-learning`, route `iqraspace.org/learning*`): static assets + the API, with bindings D1 `DB` (database `iqraspace-learning`), R2 `MATERIALS` (lesson PDFs) and Durable Object `LESSON_ROOMS` (`LessonRoom`, live Teach → Share sync). No secrets. `npm run build:cf` = `scripts/build-cf.mjs` (copy pdf.js assets, `next build` with `NEXT_BASE_PATH=/learning`, then `scripts/prepare-cf.mjs` → `dist/learning/**` + `_headers`). Deploys are CI-only (`.github/workflows/ci.yml`); never run `wrangler deploy` from a session.
- **Dynamic routes** (`share/[lessonId]`, `teach/[lessonId]`, `admin/duas/[id]`, `admin/duas/categories/[slug]`) export one placeholder shell with param `_`; the client reads the real id from the URL (`src/lib/routeParam.ts`, `RouteEntry.tsx`). `worker/routes.js` maps real URLs to the shell and `wrangler.jsonc` `assets.run_worker_first` lists the patterns (plus `/learning/api/*`). Adding a dynamic route means updating the page, `worker/routes.js`, its test `worker/routes.test.mjs` and `run_worker_first` (including `!` exclusions for sibling static pages).
- **API base URL:** a basePath build always calls the same-origin `/learning/api`; `npm run dev` (no basePath) uses `NEXT_PUBLIC_API_URL` (normally `http://localhost:8787/learning/api` from `npm run dev:api`). `NEXT_PUBLIC_BASE_PATH` is derived from `NEXT_BASE_PATH` in `next.config.ts` (plain `<img>` and pdf.js asset URLs need the prefix).
- **Auth & roles:** username + password (PBKDF2 in `worker/api/auth.js`), bearer-token sessions stored hashed in D1. `users.role`: `tutor`, `student`, `guardian`, `admin`, `super_admin` (`src/lib/roles.ts`); it only changes via the `set_user_role` RPC, and signup can never create admins (`npm run seed:admins` does). Admins get `/admin` (dashboard), `/admin/users` (Worker `/admin/users` endpoint), `/admin/duas` (`components/shell/navConfig.ts`).
- **Duas admin** (`src/app/(app)/admin/duas`, `src/components/admin/duas`, `src/lib/duas`): admin/super_admin only. Manages `duas`, `dua_categories`, `dua_category_map` with a draft → review → published (+ archived) workflow, audit log (`dua_audit_log`, written by `hooks.js`) and restore. Only published rows are public, via `GET /learning/api/duas/content` and `/duas/version` (`worker/api/duas.js`), consumed by the website (`/api/duas`, service binding) and the Flutter app (`DUAS_API_URL`). `src/lib/duas/validate.ts` is shared with the Worker (`normalizeArabic`). Unit tests: `npm run test:duas`.
- **Schema / migrations:** `d1/migrations/*.sql`, applied manually (`npm run db:migrate:local`; production `npx wrangler d1 migrations apply iqraspace-learning --remote`); CI never applies them. A schema change also needs `worker/api/schema.js` (and a `policies.js` rule for a new table); `worker/api/api.test.mjs` checks schema.js against the migration.
- **Lesson files:** private R2 bucket via the Worker (`worker/api/storage.js`, `src/lib/storage.ts`): authenticated upload, one-hour download tickets.
- **Commands:** `npm run lint`, `npx next typegen` then `npm run typecheck`, `npm run test:duas`, `npm run test:worker` (routing + API tests on `node:sqlite`), `npm run build:cf`, `npm run dev:api`.
